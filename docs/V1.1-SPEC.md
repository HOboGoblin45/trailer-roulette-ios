# v1.1 spec — Couple's Mode + Stats screen

**Status**: Draft. Locks scope for the first post-launch release.
**Target**: 4–6 weeks after v1.0 ships.
**Theme**: extend the personal-taste loop into a shared one + surface the data the loop already collects.

## Why v1.1 now

v1.0 ships with Watchlist + Seen it/Skip it. Both are inherently solo. The next obvious questions from real users will be:
1. "Can I do this with my partner?" → **Couple's Mode**
2. "What does my taste profile look like?" → **Stats screen**

Couple's Mode was the originally-recommended v1 feature; we deferred it to keep v1 small. Stats was always a v1.1 candidate. Both are pre-staged in the architecture (the taste profile already exists; we just need a UI for it).

## Feature 1 — Couple's Mode

### User story
> "We're trying to pick a movie for date night. Each of us swipes through the same trailers separately. The app shows us the ones we both swiped right on."

### UX flow
1. **Activation**: Settings → "Start Couple's Mode" → choose pairing method:
   - **Same device** (turn-taking): each person swipes; pass the phone. Profile A → swipes 10 trailers → "Pass to your partner" prompt → Profile B sees the same 10 trailers in the same order, swipes independently. Reveal the matches.
   - **Two devices** (proximity-based, post-v1.1): use Multipeer Connectivity over Wi-Fi/Bluetooth to sync trailer lists between two iPhones. Each person swipes on their own device; matches appear in real time.
2. **Match list**: a new screen shows trailers both partners swiped right on, sorted by recency
3. **Tap a match**: opens the trailer (regular playback)
4. **Save match list to Watchlist**: "Save all" or per-trailer

### Data model
Add to `KEYS` in `storage.js`:
- `COUPLES_MODE_PROFILES` — `{ A: { genre, decade, runtime }, B: { ... } }`
- `COUPLES_MODE_SESSION` — `{ active: bool, currentProfile: 'A'|'B', sessionStart: ISO, trailerIds: [], reactionsA: {id: 'seen'|'skip'}, reactionsB: {} }`
- `COUPLES_MODE_MATCHES` — array of `{ trailerId, sessionStart }`

No backend. No Sign In with Apple. Same privacy posture as v1.

### Implementation tasks
- [ ] `app/src/components/CouplesMode.jsx` — wraps the player + swipe overlay; tracks current profile
- [ ] `app/src/components/CouplesMatches.jsx` — match list screen
- [ ] `app/src/lib/couplesMode.js` — session state machine
- [ ] Settings entry to start a session
- [ ] "Pass the phone" UX (full-screen overlay with 3-2-1 countdown + the partner's name input on first run)
- [ ] After session completes, compute intersection of A-likes and B-likes
- [ ] Persist match history; ability to view past sessions

### Acceptance criteria
- [ ] Two-profile turn-taking flow works without crashes
- [ ] Match computation is correct (set intersection of right-swipes)
- [ ] Session persists across app backgrounding (e.g., user takes a phone call mid-swipe)
- [ ] Profile names are user-editable (default "Player 1" / "Player 2")
- [ ] All data stays on-device; no network calls beyond the existing TMDB/YouTube ones

### Out of v1.1
- **Two-device proximity sync** — requires Multipeer Connectivity + a real test rig. v1.2.
- **Backend match storage / sharing matches with friends** — would force Sign In with Apple. Not in scope.
- **More than 2 profiles** — three-way roommate movie night is v1.3 territory.

## Feature 2 — Stats screen

### User story
> "I want to see what genres I've been into lately, what eras of film I gravitate toward, my swipe history."

### UX
New screen accessible from About/Settings → "Your Taste":

```
┌────────────────────────────────────────────┐
│   Your Taste                            ⓧ  │
├────────────────────────────────────────────┤
│   42 Seen · 18 Skipped · 7 in Watchlist    │
├────────────────────────────────────────────┤
│   GENRES YOU LOVE                          │
│   ▮▮▮▮▮▮▮▮  Sci-Fi      +12               │
│   ▮▮▮▮▮▮     Action      +8                │
│   ▮▮▮▮       Drama       +5                │
│   ▮          Romance     -2                │
├────────────────────────────────────────────┤
│   DECADES                                  │
│   2020s ████████░░  60%                    │
│   2010s ████░░░░░░  30%                    │
│   2000s █░░░░░░░░░  10%                    │
├────────────────────────────────────────────┤
│   STREAKS                                  │
│   Current: 4 days · Longest: 12 days       │
└────────────────────────────────────────────┘
```

### Data sources
All from existing data:
- `KEYS.SEEN_LIST` and Watchlist for counts
- `KEYS.TASTE_PROFILE` for affinity buckets
- New: track session-day count for streak

### Implementation tasks
- [ ] `app/src/components/StatsScreen.jsx`
- [ ] `app/src/lib/stats.js` — derive display values from existing storage
- [ ] Bar chart component (pure CSS, no external lib)
- [ ] Streak tracker — persists last-active date, increments if today is consecutive
- [ ] Add "Reset taste profile" button (clears profile, keeps watchlist)
- [ ] Empty state when profile has no signals yet

### Acceptance criteria
- [ ] Loads in <500ms on iPhone SE
- [ ] All numbers update in real time after a swipe
- [ ] Streak tracker correctly handles missed days
- [ ] Reset flow asks for confirmation
- [ ] No telemetry; all values computed from local storage

If v1.0 is approved and live, v1.1 should follow ~5–6 weeks behind.

## Risks
- **Couple's Mode UX is hard to test alone.** TestFlight with real couples (girlfriend + a friend pair or two) is mandatory before submission.
- **App Review on v1.1**: should be straightforward as long as the privacy posture stays the same. If we add a backend later, the nutrition label changes and we're back in the 4.2 review zone.
- **Stats screen with empty profile** — make sure the empty state is delightful, not embarrassing. First-time users will see this.

## Out of v1.1 (deferred to v1.2+)
- Custom playlists ("Friday night horror," etc.)
- Localization (es, fr, de, ja)
- Multipeer two-device couple's mode
- Apple Watch glance
- Widgets
- Siri shortcut for "shuffle"
- Sign In with Apple + cross-device sync
